# 피드백·상황별 복습 수정

## 원인과 처리

이전 structure는 목록 번호를 문장으로 잘라 피드백에 넣었습니다. grouping은 팔/라켓/풋워크 같은 큰 키워드로 다른 교정을 합쳤고 groupStats는 피드백 줄 수를 셌습니다. 복습 UI는 ReviewCard.question을 사용하지 않고 기술명이 붙은 범용 문구를 렌더링했습니다.

현재 `src/coaching.ts`에서 추출 전에 목록 표기를 정리합니다. 숫자·구두점·기호·공백만 있는 항목은 제거하고 실제 내용을 남깁니다. 짧은 문자열은 길이 기준으로 삭제하지 않습니다. 기술 분류와 코칭/잘한 점/느낌 섹션을 구분합니다. 자동 그룹은 실제 교정 문구의 일치 기준으로만 연결하며, 넓은 키워드 그룹은 재처리에서 분리합니다. 정확히 다른 문구를 자동으로 의미 추론해 합치지는 않습니다. 사용자가 명시적으로 만든 그룹은 유지합니다.

같은 기록 안의 중복 문구는 저장 시 제거하고, groupStats는 그룹별 서로 다른 레슨/대회 ID를 셉니다. 목록·TOP5·공통 피드백·가져오기 결과는 ‘N개 기록에서 등장’으로 표시합니다. TOP5에서 상세 타임라인과 근거 원문을 열 수 있습니다.

질문은 원문 내 기술 heading·명시된 상황/잘못된 동작·구체적인 교정이 연결될 때 생성합니다. 여러 기술의 제목 중 하나를 임의로 고르지 않습니다. 단일 선택 기술은 기록 작성 시 맥락으로 사용하지만 교정과 근거는 반드시 rawText에서 찾습니다. 서로 다른 교정 대상이 연결된 한 문장은 독립 질문으로 분리합니다. 유효한 질문이 부족하면 5개보다 적게 출제합니다. 추출은 규칙 기반이며 모호한 문장을 억지로 해석하지 않습니다.

새 복습 카드는 상황별 직접 회상으로 생성됩니다. 정답 확인 전에는 교정 답안을 드러내지 않고, 이후에는 교정과 실제 원문 구절·출처를 함께 표시합니다. 자유 답변은 표현 일치로 평가하지 않고 ‘기억했어요 / 일부만 기억했어요 / 다시 볼래요’로 직접 평가합니다. 일부 기억은 단계 유지·다음날 재복습이며 별도 partialCount를 남깁니다. 기존 세션의 total=correct+incorrect 호환성을 위해 세션의 incorrect에는 일부 기억도 포함하되 화면에서는 세 값을 분리해 표시합니다.

예시 입력(검증용):

```
스매시 수비에서 어깨가 들리고 팔 힘으로만 공을 높이 보내던 동작
1.
어깨 힘 빼기
```

이전 질문: ‘이 기술에서 코치가 강조한 말을 떠올려보세요.’

현재 질문: ‘스매시 수비에서 어깨가 들리고 팔 힘으로만 공을 높이 보내던 동작, 어깨의 힘 사용에 대해 어떤 교정을 받았나요?’

정답은 기록에 있는 ‘어깨 힘 빼기’이며 상황과 교정 사이에 있는 목록 번호까지 포함한 원문을 근거로 확인할 수 있습니다. 실제 사용자 기록에 이 문장을 주입하지 않습니다.

## 기존 데이터 반영

`src/reprocess.ts`는 `settings.coachingVersion=2`를 기준으로 한 번 재처리합니다. 원문·날짜·출처·회차/범위·코치·createdAt/updatedAt는 유지합니다. 의미 있는 사용자 편집 피드백도 보존합니다. 번호나 분류뿐인 피드백·모호한 카드·고아 그룹은 재생성된 파생 데이터로 교체합니다. 유효한 피드백/카드 ID와 기존 복습 간격·정답/오답 횟수를 가능한 한 유지합니다. 중복 피드백 ID는 세션의 wrongFeedbackIds에도 다시 연결합니다. 과거 세션의 점수 자체는 지우지 않습니다. 번호뿐인 자동 집중 포인트도 유효한 교정으로 바꿉니다.

localStorage: repository.load에서 검증→기존 전체 DB 안전 사본→재처리 결과 저장. 안전 사본은 `kokrecall:coaching-safety:v2`입니다. 저장 공간 오류라면 기존 DB를 교체하지 않습니다.

Supabase: cloudAccess.load에서 검증→계정별 브라우저 안전 사본→revision을 검사한 원자적 저장. 안전 사본은 `kokrecall:coaching-safety:v2:user:사용자ID`입니다. 충돌·네트워크 오류라면 성공으로 표시하지 않습니다. 재처리 완료 메시지가 표시되고 설정에서 이전 데이터를 내려받을 수 있습니다. 백업 복원 시에도 오래된 파생 데이터는 현재 추출 방식으로 전환합니다.

이 로직은 수정본을 실행하고 기존 데이터를 로딩할 때 적용됩니다. 작업 환경에서 스마트폰 localStorage나 실제 Supabase DB에 접근해 직접 변경한 것은 아닙니다. 재가져오기는 필요하지 않습니다. 안전 사본에는 기존 DB 전체가 들어가며 개인 데이터용 Git 제외 규칙이 유지됩니다.

## 검증

자동 테스트 53개 통과: 기존 동작·혼합 TXT·데이터 보존 외에 목록 번호/붙은 번호/분리된 번호/유니코드 숫자/기호, 짧은 피드백 보존, 중복 기록 기준 집계, 다른 교정 분리, 여러 기술 맥락, 답안 비노출, 교정 없는 기록 제외, 재처리 멱등성·스케줄·안전 사본·저장 실패·cloud revision 충돌, 질문/답변 React 렌더링을 확인했습니다.

2026-10-11 Supabase SDK 설치 후 전체 `npx tsc --noEmit` 및 `npm run build` 통과. Auth·CRUD·Supabase adapter를 포함한 전체 앱을 실제 SDK 타입으로 검사했습니다. 실제 서버 로그인·RLS·저장 결과는 아직 검증하지 않았습니다.

모바일은 430px 이하에 질문 23px, 본문/입력 16px, 세로 자기평가 버튼 52px 이상, 원문 자동 줄바꿈·넉넉한 행간을 적용했습니다. 질문·답변 HTML 렌더링은 검증했습니다. 실제 390px Chrome 스크린샷은 실행 환경에서 브라우저가 종료되어 검증하지 못했습니다. `artifacts/review-question.html`, `artifacts/review-answer.html`은 샘플로 생성한 로컬 점검용이며 Git에서 제외됩니다. 실제 스마트폰 키보드·스크롤·터치는 별도로 확인해야 합니다.
